# Пошаговая инструкция для администратора GND Admin

Подробная последовательность действий для первичной настройки и ежедневной работы с админ-панелью GND (ГАНИМЕД Blockchain).

Сводную настройку (нода, админка, кошелёк, native_contracts.json) см. в отдельной статье: **Сводная настройка: нода, админка, кошелёк и native_contracts.json**.

---

## Часть 1. Первый запуск и подготовка окружения

### Шаг 1.1. База данных ноды GND_v1

1. Убедитесь, что PostgreSQL запущен и создана БД `gnd_db` (пользователь `gnduser` или по вашей конфигурации).
2. Примените миграции ноды **по порядку** из каталога `GND_v1/db/migrations/`:
   - 001–005 — базовые таблицы (blocks, transactions, accounts и т.д.).
   - 006 — API-ключи и админ: `psql -U gnduser -d gnd_db -f db/migrations/006_api_keys_admin.sql`
   - 007 — имена и роли кошельков: `db/migrations/007_wallets_name_role.sql`
   - 008 — отключение подписания (disabled): `db/migrations/008_wallets_disabled.sql`
   - 014 — снимки состояний и storage контрактов (если используете чтение/запись состояний).
   - 017 — дополнительные колонки контрактов (code, standard и т.д.).
   - 018 — колонка `state_root` в таблице блоков.
3. Проверьте, что таблицы `blocks`, `transactions`, `wallets`, `contracts`, `api_keys` существуют.

### Шаг 1.2. Переменные окружения ноды (GND_v1)

В каталоге ноды задайте в `.env` или в переменных окружения:

| Переменная | Назначение |
|------------|------------|
| `GND_MASTER_KEY` | 64 hex-символа (32 байта) — мастер-ключ для подписи кошельков. Обязателен для создания кошельков через API. |
| `GND_ADMIN_SECRET` | Секретный токен для админ-API (X-Admin-Token). Должен совпадать с значением в GND_admin. |
| `GND_API_KEY` | (Опционально.) API-ключ для создания кошельков. Если не задан, кошельки можно создавать только с X-Admin-Token. |
| Подключение к БД | По конфигу ноды (например `config/db.json`) — хост, порт, имя БД, пользователь, пароль. |

Пример (без реальных секретов):

```env
GND_MASTER_KEY=0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
GND_ADMIN_SECRET=your-admin-secret-token
GND_API_KEY=optional-api-key-for-wallet-creation
```

### Шаг 1.3. Запуск ноды GND_v1

1. Перейдите в каталог ноды: `cd GND_v1`
2. Запустите: `go run main.go` (или собранный бинарник).
3. Убедитесь, что REST API доступен (по умолчанию порт 8182): откройте в браузере или `curl http://127.0.0.1:8182/api/v1/health` (если есть такой эндпоинт) или проверьте логи — «REST server listening on :8182».

### Шаг 1.4. Переменные окружения GND_admin

В каталоге **GND_admin** в файле `.env` задайте:

| Переменная | Назначение |
|------------|------------|
| `GND_NODE_URL` | URL ноды, например `http://127.0.0.1:8182` (без завершающего слэша). |
| `GND_ADMIN_SECRET` | То же значение, что и `GND_ADMIN_SECRET` на ноде. Иначе запросы с X-Admin-Token будут отклоняться. |
| `GND_API_KEY` | (Опционально.) API-ключ для создания кошельков через админку; должен совпадать с тем, что принимает нода. |

Пример:

```env
GND_NODE_URL=http://127.0.0.1:8182
GND_ADMIN_SECRET=your-admin-secret-token
GND_API_KEY=optional-api-key-for-wallet-creation
```

### Шаг 1.5. Запуск GND_admin и первый вход

1. Установите зависимости: `composer install`, при необходимости `npm install && npm run build`.
2. Выполните миграции Laravel: `php artisan migrate`.
3. Создайте админ-пользователя (если ещё нет): через сидер `AdminUserSeeder` или вручную — пользователь с ролью `admin`.
4. Запустите приложение: `php artisan serve` (по умолчанию порт 8000).
5. Откройте в браузере: `http://127.0.0.1:8000`, войдите под учётной записью с ролью **admin**.

## Часть 2. Работа с кошельками

### Шаг 2.1. Создание кошелька

1. В меню выберите **Кошельки** → **Создать кошелёк**.
2. Нажмите **Создать** (форма может быть без дополнительных полей — кошелёк создаётся запросом к ноде).
3. Ожидаемый результат: редирект на список кошельков, сообщение «Кошелёк создан», в таблице появилась строка с адресом (GND...).
4. Если ошибка: проверьте `GND_NODE_URL`, `GND_API_KEY` в GND_admin и `GND_MASTER_KEY` на ноде.

### Шаг 2.2. Просмотр кошелька

1. На странице **Кошельки** нажмите по адресу или кнопке **Подробнее** нужного кошелька.
2. На странице просмотра отображаются: адрес, имя, роль, Signer Wallet ID, дата создания, статус подписания (Активно/Заблокировано), таблица балансов (GND, GANI, токены по контрактам).

### Шаг 2.3. Изменение имени и роли

1. В списке или на странице кошелька нажмите **Имя/роль** (или «Редактировать»).
2. Введите **Имя** и/или **Роль** (например `validator`, `treasury`).
3. Нажмите **Сохранить**. Должно появиться сообщение «Кошелёк обновлён».

### Шаг 2.4. Блокировка и разблокировка подписания

- **Блокировка:** в списке или на странице кошелька нажмите **Блокировать**. Подписание отключено, в статусе — «Заблокирован».
- **Разблокировка:** нажмите **Разблокировать**. Статус — «Активен».

Кошелек должен быть создан через ноду с привязкой к Signer (иметь Signer Wallet ID), иначе кнопки блокировки/разблокировки могут быть недоступны.

### Шаг 2.5. Мягкое удаление кошелька

1. Нажмите **Удалить** у нужного кошелька.
2. Подтвердите в диалоге. Кошелёк исчезнет из списка (мягкое удаление: запись в БД остаётся с `disabled = true`).

## Часть 3. Контракты

### Шаг 3.1. Добавление контракта в каталог

1. Перейдите в **Контракты** → **Создать контракт**.
2. Заполните название, адрес (если уже задеплоен), стандарт (например GNDst-1), описание — по необходимости.
3. Сохраните. Контракт появится в списке (каталог в БД GND_admin).

### Шаг 3.2. Компиляция и деплой

1. Откройте карточку контракта (**Контракты** → выберите контракт).
2. Загрузите или вставьте код Solidity, при необходимости укажите стандарт.
3. Нажмите **Компилировать** — проверка кода и получение ABI/байткода.
4. Нажмите **Деплой** — отправка транзакции деплоя на ноду. После включения в блок контракт получит адрес; сохраните его в карточке контракта.

Все действия (создание записи контракта, компиляция, деплой, запись storage, вызов методов) формируют транзакции в блокчейне и отображаются в разделе **Транзакции**.

### Шаг 3.3. Просмотр, чтение и запись контракта

- **Просмотр:** на странице контракта отображаются данные из каталога (адрес, имя, стандарт, код, ABI).
- **Чтение контракта:** вкладка «Прочитать контракт» — список методов контракта из ABI; вызов **view/pure** методов без изменения состояния (чтение балансов, totalSupply и т.д.).
- **Запись контракта:** вкладка «Записать контракт» — вызов методов, изменяющих состояние (transfer, approve, setGaniToken и т.д.); выполняется через отправку транзакции на ноду.

**Как подписать транзакцию из админки**

Транзакции вызова методов контракта (запись) должны быть подписаны. В админке подпись выполняется **автоматически нодой**, если выполнены условия:

1. **Нода запущена с переменной `GND_MASTER_KEY`** (тот же мастер-ключ, под которым создавались кошельки через ноду).
2. **В GND_admin в `.env` задан `GND_ADMIN_SECRET`**, совпадающий с `GND_ADMIN_SECRET` на ноде — админка отправляет заголовок `X-Admin-Token` при вызове «Записать контракт».
3. **Кошелёк (from)** выбран из списка кошельков, созданных через ноду (у него есть **Signer Wallet ID** в БД ноды). Для таких кошельков ключ хранится в `signer_wallets` на ноде; при запросе из админки с валидным X-Admin-Token нода сама подписывает транзакцию и помечает её как верифицированную.

Если вы видите ошибку «транзакция должна быть подписана (signature обязателен)» — проверьте: нода запущена с `GND_MASTER_KEY`, в админке задан `GND_ADMIN_SECRET`, выбранный кошелёк создан через ноду (имеет signer_wallet_id). Кошельки, созданные вручную или без signer_wallets, для записи из админки не подходят — для них нужна отдельная подпись (вне админки).

Убедитесь, что нода запущена и контракт задеплоен (адрес контракта известен ноде), иначе возможна ошибка «Контракт не найден на ноде (404)».

## Часть 4. Токены (GND, GANI и кастомные)

### Шаг 4.1. Нативные токены GND и GANI

- **GND** (Ganimed) и **GANI** (Ganimed Governance) — нативные монеты; при первом запуске ноды они могут быть не задеплоены.
- Адреса контрактов GND/GANI задаются в конфигурации ноды (например `native_contracts.json` или `coins.json`). После деплоя контрактов GND и GANI на ноде необходимо прописать их адреса в конфиге ноды, чтобы балансы и total_supply отображались в админке (раздел «Предложение» на дашборде).
- В админке балансы GND/GANI по кошелькам отображаются на странице кошелька (блок «Балансы токенов») и на дашборде (total_supply и циркуляция).

### Шаг 4.2. Каталог токенов и привязка к контрактам

1. Раздел **Токены** — каталог токенов (записи в БД GND_admin).
2. **Создать токен:** укажите символ, имя, адрес контракта (если токен уже задеплоен), стандарт.
3. **Деплой токена:** используйте **Токены** → **Деплой токена**, если в системе предусмотрен сценарий деплоя токен-контракта через ноду.
4. Токены, привязанные к адресу контракта, отображаются в балансах кошельков (если нода отдаёт их через API балансов).

## Деплой GND и GANI через админку (Вариант А)

Ниже — пошаговые действия простыми словами: взять файл с кодом, вставить в админку, задеплоить, взять адрес и вписать в конфиг ноды. Коды контрактов лежат в ноде в папке **GND_v1/tokens/standards/deploy_order/** — номера в названиях файлов задают порядок деплоя.

### Что понадобится

- Нода GND_v1 запущена, админка открыта, вы вошли как администратор.
- Открыть на компьютере папку с нодой: **GND_v1/tokens/standards/deploy_order/**.
- Блокнот или файл, куда будете записывать адреса после каждого деплоя.

---

### Шаг 1. Деплой контроллера (первый контракт)

1. В админке откройте **Контракты** → **Создать контракт**.
2. Заполните название, например: **NativeTokensController**.
3. В поле с кодом контракта (Solidity) **вставьте весь код** из файла **01_NativeTokensController.sol** из папки `deploy_order` (можно открыть файл в блокноте и скопировать).
4. Нажмите **Сохранить** (если нужно сохранить карточку контракта).
5. Нажмите **Компилировать**. Дождитесь успешной компиляции.
6. Нажмите **Деплой**. Параметры конструктора не нужны — конструктор пустой.
7. После успешного деплоя **скопируйте адрес контракта** (он появится на странице или в данных контракта). Запишите его, например: **Адрес контроллера: GND...**
8. Этот адрес понадобится в шагах 2 и 3.

---

### Шаг 2. Деплой токена GND

1. В админке снова **Контракты** → **Создать контракт**.
2. Название, например: **GNDToken**.
3. В поле кода **вставьте весь код** из файла **02_GNDToken.sol** из папки `deploy_order`.
4. Сохраните, нажмите **Компилировать**.
5. Нажмите **Деплой**. Конструктору нужны **два параметра**:
   - **Первый параметр (initialSupply):** число **1000000000000000000000000000** (это 1e27 — полная эмиссия GND в наименьших единицах).
   - **Второй параметр (controllerContract):** **адрес контроллера из шага 1** (тот, что вы записали).
6. После деплоя **скопируйте адрес контракта GND** и запишите: **Адрес GND: GND...**

---

### Шаг 3. Деплой токена GANI

1. **Контракты** → **Создать контракт**.
2. Название, например: **GANIToken**.
3. В поле кода **вставьте весь код** из файла **03_GANIToken.sol** из папки `deploy_order`.
4. Сохраните, нажмите **Компилировать**.
5. Нажмите **Деплой**. Конструктору нужен **один параметр**:
   - **Адрес контроллера** — тот же, что в шаге 1 (и в шаге 2).
6. После деплоя **скопируйте адрес контракта GANI** и запишите: **Адрес GANI: GND...**
7. **(Опционально)** Чтобы контроллер мог выпускать GANI (функция `mintGANI`): откройте карточку контракта **NativeTokensController** в админке, вкладка «Записать контракт», вызовите метод **setGaniToken** с параметром — адрес GANI из шага 3. Вызов должен выполнять владелец контроллера (адрес, с которого деплоился контроллер).

---

### Шаг 4. Вписать адреса в конфиг ноды

1. Остановите ноду GND_v1 (если запущена).
2. Откройте на сервере (или на своём компьютере, где лежит нода) файл **GND_v1/config/native_contracts.json**.
3. В поле **gnd_contract_address** вставьте **адрес GND из шага 2**.
4. В поле **gani_contract_address** вставьте **адрес GANI из шага 3**.
5. Сохраните файл. Поля `fee_collector_address` и `gndself_address` при необходимости заполните отдельно (можно оставить как есть, если уже заданы).
6. Запустите ноду снова.

Пример, как должен выглядеть фрагмент файла после правок:

```json
"gnd_contract_address": "GNDxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
"gani_contract_address": "GNDyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy",
```

(подставьте свои адреса вместо x и y).

---

### Шаг 5. Проверка

1. После запуска ноды откройте дашборд админки. В блоке «Предложение» должны отображаться total_supply и циркуляция для GND и GANI (если нода отдаёт эти данные по API).
2. Откройте любой кошелёк — в блоке «Балансы токенов» при наличии балансов должны быть строки по GND и GANI.

Если балансы или предложение не появляются — проверьте, что адреса в `native_contracts.json` совпадают с теми, что вы задеплоили, и что в БД ноды есть записи в таблицах `contracts` и `tokens` для этих контрактов (при необходимости их добавляют через миграции или вручную по документации ноды).

## Часть 5. Транзакции

### Шаг 5.1. Просмотр списка транзакций

1. Меню **Транзакции** — список транзакций.
2. Данные подтягиваются с ноды (например GET `/api/v1/transactions/list`) и/или из локальной БД GND_admin (таблица `transactions` для записей, созданных через админку).
3. Если список пуст: проверьте `GND_NODE_URL` и `GND_ADMIN_SECRET` в `.env`; убедитесь, что нода записывает транзакции в БД и что блоки производятся (интервал создания блоков в конфиге консенсуса).

### Шаг 5.2. Создание транзакции (перевод)

1. **Транзакции** → **Создать транзакцию**.
2. Укажите получателя, сумму, при необходимости данные контракта.
3. Отправьте. Транзакция уходит на ноду, попадает в mempool и должна быть включена в следующий блок; в списке транзакций появится новая запись.

## Часть 6. API-ключи приложений

1. **Ключи приложений** — управление ключами, хранящимися на ноде (создание, список, отзыв).
2. Создание ключа: укажите имя, при необходимости права и срок действия; ключ один раз отображается в ответе (сохраните его).
3. Для доступа к админ-маршрутам ноды используется не этот ключ, а заголовок **X-Admin-Token** со значением `GND_ADMIN_SECRET`. API-ключи используются для операций от имени приложений (например создание кошельков с `X-API-Key`).

---

## Часть 7. API (REST, WS, RPC)

1. Раздел **API (REST, WS, RPC)** — справочная страница: базовый URL ноды, основные маршруты, примеры запросов.
2. Кнопка **Отправить запрос** позволяет отправить тестовый запрос к выбранному эндпоинту ноды (для проверки подключения и формата ответа).

## Часть 8. Рекомендуемый порядок действий при первом запуске

1. **Нода:** применить миграции БД (шаг 1.1), задать `GND_MASTER_KEY`, `GND_ADMIN_SECRET` (и при необходимости `GND_API_KEY`), запустить ноду (1.2–1.3).
2. **GND_admin:** задать в `.env` `GND_NODE_URL`, `GND_ADMIN_SECRET`, `GND_API_KEY` (1.4), запустить приложение, войти под admin (1.5).
3. **Проверка связи:** на дашборде в блоке «Цепочка» должны отображаться количество блоков и транзакций; при отсутствии — проверить URL и секрет.
4. **Кошельки:** создать хотя бы один кошелёк (2.1), открыть его (2.2), при необходимости изменить имя/роль (2.3).
5. **Контракты:** при необходимости добавить контракт, скомпилировать и задеплоить (3.1–3.2); проверить чтение/запись (3.3).
6. **Токены GND/GANI:** задеплоить контракты по разделу **«Деплой GND и GANI через админку (Вариант А)»** (файлы в GND_v1/tokens/standards/deploy_order/), вписать адреса в `config/native_contracts.json` на ноде; проверить отображение предложения на дашборде.
7. **Транзакции:** выполнить тестовый перевод или вызов контракта, убедиться, что транзакция появляется в списке и в блоке.

## Типичные ошибки и проверки

| Проблема | Что проверить |
|----------|----------------|
| Список кошельков пуст при работающей ноде | `GND_NODE_URL`, `GND_ADMIN_SECRET` в `.env` GND_admin; миграции 007, 008 на ноде. |
| Ошибка при создании кошелька | `GND_API_KEY` в GND_admin; `GND_MASTER_KEY` (64 hex) на ноде. |
| Контракт не найден на ноде (404) | Нода запущена; контракт задеплоен и его адрес сохранён в карточке контракта; эндпоинты состояний/контрактов доступны. |
| Нет транзакций в списке | На ноде применены миграции для таблицы `transactions`; блоки производятся; `GND_NODE_URL` и `GND_ADMIN_SECRET` заданы. |
| Блоки не создаются | Конфиг консенсуса (интервал блоков); логи ноды (ошибки при производстве блока); наличие транзакций в mempool. |
| Блокировка/разблокировка кошелька недоступна | Кошелёк создан через ноду с Signer (есть Signer Wallet ID). |
