# Сценарий тестирования контрактов (GND_admin + GND_v1)

## Цель
Проверка: генерация контракта, сохранение (в т.ч. ABI в gnd_db), работа с методами (call/send), редактирование.

## Предусловия
- Нода GND_v1 запущена, БД gnd_db доступна.
- В `.env` админки заданы `GND_API_URL` и `GND_ADMIN_SECRET`.
- Пользователь с ролью admin.

---

### 1. Генерация и сохранение (GND_admin)
1. Войти в админку → Контракты → Создать контракт.
2. Заполнить название, описание, вставить Solidity-код (например простой контракт с `function transfer()`).
3. Сохранить → контракт в статусе draft.
4. Нажать **1. Компилировать** → статус обновлён, в БД админки сохранены `bytecode_hex`, `abi_json`.
5. Выбрать кошелёк и нажать **Задеплоить на ноду** → в gnd_db на ноде создаётся запись в `contracts` с полем `abi` (не NULL, если при деплое передан ABI).

### 2. Исправление abi = NULL в gnd_db (если контракт был задеплоен без ABI)
- **Один контракт:** страница контракта → кнопка **«Обновить ABI на ноде»** (отправляет локальный `abi_json` в PATCH `/api/v1/admin/contracts/:address/abi`).
- **Все контракты:** список контрактов → **«Обновить ABI на ноде (все)»** — для каждого контракта с адресом и ABI вызывается PATCH.

### 3. Синхронизация node_contract_id
- Список контрактов → **«Синхронизировать с нодой»** — для контрактов с адресом запрашивается id на ноде (GET `/api/v1/contract/:address`) и сохраняется в `node_contract_id`.

### 4. Работа с методами (call / send)
1. Открыть контракт (страница просмотра).
2. Вкладка **«Чтение контракта»**: выбрать view/pure метод, ввести аргументы → Выполнить → ответ от ноды (POST `/api/v1/admin/contracts/by-id/:id/call`).
3. Вкладка **«Запись в контракт»**: выбрать метод записи, ввести аргументы и адрес отправителя → Отправить → транзакция (POST `/api/v1/admin/contracts/by-id/:id/send`).
- Для call/send используется `node_contract_id`; если он пуст, админка пытается получить id по адресу и сохранить.

### 5. Редактирование (GND_admin)
- Контракт → **Изменить**: изменить название, описание, исходный код. После изменения кода снова выполнить компиляцию перед повторным деплоем.

### 6. Редактирование на ноде (GND_v1)
- Обновление только ABI: `PATCH /api/v1/admin/contracts/:address/abi` с телом `{"abi": [...]}` (заголовок `X-Admin-Token`). Остальные поля контракта на ноде при этом не меняются.

---

## Автотесты
- **GND_v1:** `go test ./api -run "TestAdminUpdateContractABI|TestCompile|TestHealth"` — проверка эндпоинта обновления ABI, компиляции, health.
- **GND_admin:** `php artisan test tests/Feature/ContractTest.php` — список, просмотр, update-abi-on-node, sync-abi-to-node, sync-from-node.
