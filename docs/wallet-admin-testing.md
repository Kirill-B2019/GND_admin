# Тестирование раздела «Кошельки» в GND_admin

**Цель:** проверить создание кошелька, просмотр, изменение имени/роли, блокировку подписания и мягкое удаление.

---

## Состояния контрактов (API)

GND_admin может читать и записывать состояния контрактов через ноду:

- **Чтение:** `GndAdminApi::getAccountStateCurrent($address)` — текущее состояние аккаунта (GET /api/v1/state/account/:address); `GndAdminApi::getAccountStateAtBlock($address, $blockId)` — снимок на блок; `GndAdminApi::getContractStorage($address, $blockId)` — слоты storage контракта на блок (GET /api/v1/state/contract/:address/storage?block_id=).
- **Запись:** `GndAdminApi::writeContractStorageSlot($address, $blockId, $slotKey, $slotValue)` — запись слота (POST /api/v1/admin/state/contract/:address/storage, требуется X-Admin-Token).

Для работы эндпоинтов состояний на ноде должна быть применена миграция **014** (account_states, contract_storage). См. docs/api.md и docs/admin-api.md в GND_v1.

---

## Предусловия

1. **Нода GND_v1** запущена (REST на порту 8182), применены миграции 006, 007, 008 и при использовании состояний — 014:
   ```bash
   psql -U gnduser -d gnd_db -f db/migrations/006_api_keys_admin.sql
   psql -U gnduser -d gnd_db -f db/migrations/007_wallets_name_role.sql
   psql -U gnduser -d gnd_db -f db/migrations/008_wallets_disabled.sql
   ```
2. В ноде заданы: `GND_MASTER_KEY` (64 hex), `GND_ADMIN_SECRET`, при необходимости `GND_API_KEY`.
3. **GND_admin** запущен (`php artisan serve` или через веб-сервер), в `.env` заданы:
   - `GND_NODE_URL` — URL ноды (например `http://127.0.0.1:8182`),
   - `GND_API_KEY` — API-ключ для создания кошельков,
   - `GND_ADMIN_SECRET` — тот же секрет, что и на ноде.
4. В системе есть пользователь с ролью **admin**, под ним выполняется вход.

## 1. Создание кошелька

**Шаги:**

1. Открыть `http://127.0.0.1:8000/admin/wallets` (или свой хост).
2. Нажать **«Создать кошелёк»**.
3. На странице создания нажать **«Создать»** (форма может быть без полей — кошелёк создаётся через POST к ноде).
4. Ожидание: редирект на список кошельков, сообщение «Кошелёк создан», в таблице появилась новая строка с адресом (GND...).

**Проверка через API (опционально):**

```bash
curl -X POST "http://127.0.0.1:8182/api/v1/wallet" \
  -H "X-API-Key: YOUR_GND_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

В ответе должен быть `data.Address` или `data.address`.

---

## 2. Просмотр кошелька

**Шаги:**

1. На странице списка кошельков (`/admin/wallets`) нажать по **адресу** кошелька или кнопку **«Подробнее»**.
2. Открывается страница с:
   - блоком **«Данные кошелька»**: адрес, имя, роль, Signer Wallet ID, дата создания, статус подписания (Активно/Заблокировано);
   - блоком **«Балансы токенов»**: таблица балансов по токенам (данные с GET `/api/v1/wallet/:address/balance`).

**Ожидание:** данные отображаются без ошибок; при отсутствии балансов показывается «Нет записей о балансах по этому адресу» или таблица с нулями.

---

## 3. Изменение имени и роли

**Шаги:**

1. В списке или на странице просмотра нажать **«Имя/роль»**.
2. Ввести **Имя** (например `Тестовый кошелёк`) и/или **Роль** (например `validator`).
3. Нажать **«Сохранить»**.
4. Ожидание: редирект на список, сообщение «Кошелёк обновлён».
5. Снова открыть кошелёк (Подробнее) — в блоке «Данные кошелька» отображаются новые имя и роль.

**Проверка через API:**

```bash
curl -X PATCH "http://127.0.0.1:8182/api/v1/admin/wallets/GND_АДРЕС_КОШЕЛЬКА" \
  -H "X-Admin-Token: YOUR_GND_ADMIN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"name":"Treasury","role":"treasury"}'
```

---

## 4. Блокировка подписания

**Условие:** кошелёк должен быть создан через ноду с signing_service (в списке есть **Signer ID**). Кошельки без signer_wallet_id нельзя заблокировать через этот функционал.

**Шаги:**

1. В списке кошельков для нужной строки нажать **«Блокировать»** (или на странице просмотра — кнопку **«Блокировать»**).
2. Ожидание: редирект на список, сообщение «Кошелёк заблокирован (подписание отключено)».
3. В таблице в колонке **«Статус»** у этого кошелька — **«Заблокирован»** (badge жёлтый).
4. На странице просмотра в блоке «Данные кошелька» в поле «Подписание» — **«Заблокировано»**.

**Проверка через API:**

```bash
curl -X POST "http://127.0.0.1:8182/api/v1/admin/wallets/GND_АДРЕС/disable" \
  -H "X-Admin-Token: YOUR_GND_ADMIN_SECRET"
```

Ответ: `{"success":true,"data":{"disabled":true}}`.

---

## 5. Разблокировка подписания

**Шаги:**

1. Для заблокированного кошелька нажать **«Разблокировать»** (в списке или на странице просмотра).
2. Ожидание: редирект на список, сообщение «Кошелёк разблокирован», в колонке «Статус» — **«Активен»**, на странице просмотра — «Подписание: Активно».

**Проверка через API:**

```bash
curl -X POST "http://127.0.0.1:8182/api/v1/admin/wallets/GND_АДРЕС/enable" \
  -H "X-Admin-Token: YOUR_GND_ADMIN_SECRET"
```

---

## 6. Мягкое удаление

**Шаги:**

1. В списке или на странице просмотра нажать **«Удалить»**.
2. Подтвердить в диалоге «Удалить кошелёк из списка (мягкое удаление)?».
3. Ожидание: редирект на список, сообщение «Кошелёк удалён (мягкое удаление)», **эта строка исчезает из таблицы** (кошелёк больше не возвращается в GET /api/v1/admin/wallets).
4. Запись в БД в таблице `wallets` остаётся с `disabled = true`.

**Проверка через API:**

```bash
curl -X DELETE "http://127.0.0.1:8182/api/v1/admin/wallets/GND_АДРЕС" \
  -H "X-Admin-Token: YOUR_GND_ADMIN_SECRET"
```

Ответ: `{"success":true,"data":{"deleted":true}}`. После этого GET `/api/v1/admin/wallets` не вернёт этот кошелёк.

## Краткий чек-лист

| # | Действие              | Ожидаемый результат                          |
|---|------------------------|----------------------------------------------|
| 1 | Создать кошелёк        | Появился в списке с адресом GND...           |
| 2 | Открыть «Подробнее»    | Данные кошелька + балансы (или пусто)       |
| 3 | Изменить имя/роль      | Сохранено, отображается при повторном открытии |
| 4 | Блокировать            | Статус «Заблокирован», подписание отключено |
| 5 | Разблокировать         | Статус «Активен»                             |
| 6 | Удалить (мягко)        | Строка исчезла из списка                     |

## Типичные ошибки

- **Список кошельков пуст при работающей ноде** — проверить `GND_NODE_URL` и `GND_ADMIN_SECRET` в `.env` GND_admin; проверить, что на ноде применена миграция 008 и в списке не отфильтрованы все кошельки (например, все помечены как disabled).
- **Ошибка при создании кошелька** — проверить `GND_API_KEY` и что на ноде задан `GND_MASTER_KEY` (64 hex) для signing_service.
- **Блокировать/Разблокировать не отображаются** — у кошелька нет привязки к signer_wallets (создан не через текущую ноду с signing_service или старый кошелёк без signer_wallet_id).
- **404 при disable/enable/delete** — неверный адрес или кошелёк уже мягко удалён (для disable/enable).
